# Amazon Kit · 亚马逊运营工具箱

## 定位

这个技能处理亚马逊运营中**有数据的那一半**:报表进来,结论和动作出去。

运营场景里最容易出错的不是算不出指标,而是:
- 把不同口径的数字混着比(广告销售额 vs 总销售额、同步延迟的日期区间)
- 在样本量不足时下结论(点击 7 次就判定一个词"不行")
- 给出的建议没法执行("优化广告结构"这种话等于没说)

本技能的核心约束就是防这三件事。

## 处理数据文件的铁律

亚马逊后台报表的列名会随站点语言、报表版本、导出方式变化。**永远先探查再计算,不要凭记忆写死列名。**

拿到文件后的固定动作:

```bash
# 先看结构,别急着算
head -5 report.csv
python3 -c "import pandas as pd; d=pd.read_csv('report.csv'); print(d.shape); print(list(d.columns)); print(d.dtypes)"
```

然后:
1. 把实际列名映射到你要用的指标,**把映射结果告诉用户**(例如"我用 `Spend` 作为花费,`7 Day Total Sales` 作为广告销售额")。
2. 检查数据质量:日期范围、是否有汇总行、货币符号与千分位是否让数字变成了字符串、空值比例。
3. 发现列名对不上或存在多个候选列时,直接问用户,不要挑一个继续算。

常见后台报表编码是 UTF-8-SIG 或 UTF-16(制表符分隔),读取失败时依次尝试 `encoding='utf-8-sig'`、`encoding='utf-16', sep='\t'`。

## 指标定义

用这些定义,并在输出中保持口径一致:

| 指标 | 公式 | 说明 |
|---|---|---|
| ACOS | 广告花费 / 广告销售额 | 只看广告自身效率 |
| TACOS | 广告花费 / **总**销售额 | 看广告对整体生意的负担,判断自然位成长 |
| ROAS | 广告销售额 / 广告花费 | ACOS 的倒数,英文语境更常用 |
| CTR | 点击 / 曝光 | 低通常是主图、价格、评分的问题,不是广告的问题 |
| CVR | 订单 / 点击 | 低通常是详情页的问题 → 转 `detail-master` |
| CPC | 花费 / 点击 | 竞争强度与竞价水平 |
| 盈亏平衡 ACOS | 单位毛利 / 售价 | 广告花到这个比例就不赚不亏,是所有优化的基准线 |

**盈亏平衡 ACOS 必须先算。** 没有它,"ACOS 35% 高不高"这个问题根本无法回答 —— 毛利率 50% 的产品 35% 很健康,毛利率 25% 的产品 35% 在亏钱。如果用户没提供成本结构(采购价、头程、FBA 费用、佣金),先问。

## 样本量门槛

在给"砍掉"或"加大"的建议前,先确认样本够不够。经验门槛(可根据类目转化率调整,但要说明):

- 判断一个搜索词是否该否定:至少累计 **10 次点击且 0 订单**,或花费超过 1 个单位毛利仍无转化
- 判断一个词值得提价:至少 **2 个以上订单**,且 ACOS 低于盈亏平衡线
- 曝光低于几百的词:数据不足以判断,标注"继续观察"而不是下结论

样本不足时,如实说"数据量不够,建议再跑 X 天",这比编一个结论有用得多。

## 常见任务

### 广告报表分析
分层输出:账户 → 广告活动 → 广告组 → 关键词/搜索词。每层给出花费占比、ACOS、与盈亏平衡线的差距。重点标出**花费 Top 20 且 ACOS 高于盈亏平衡线**的对象,那里是最大的止血点。

### 搜索词报告 / 否词
输出三张表:
- **该否定的词**(附点击数、花费、0 订单证据)
- **该拓词的词**(已出单但还在自动/宽泛匹配里,建议提到手动精准)
- **该提价的词**(ACOS 低于盈亏平衡线且有排名空间)

否词要区分否定精准与否定词组,并说明理由 —— 否错了会连带砍掉有效流量。

### ABA / 关键词研究
按搜索频率排名分档,标注竞品集中度(点击份额是否被 1–2 个 ASIN 垄断)。垄断度高的大词对新品往往是流量陷阱,要明确提示。

### 评论 VOC 分析
按主题聚类(质量、尺寸、包装、物流、说明书、与描述不符),统计各主题占比与星级分布。产出两类动作:**产品端改进**(给供应链)与**详情页改进**(给 `detail-master`)。

### 费用与利润测算
拆到单位:售价 − 佣金 − FBA 配送费 − 采购成本 − 头程 − 退货损耗 − 广告分摊 = 净利。列出每一项的来源,标注哪些是用户给的、哪些是你的假设。

## 输出格式

```
## 结论
[3 条以内,每条一句话,先说结论再说依据]

## 数据说明
- 文件:xxx.csv,日期范围 YYYY-MM-DD ~ YYYY-MM-DD,N 行
- 列名映射:花费 = `Spend`,广告销售额 = `7 Day Total Sales (₹)` ……
- 数据问题:[缺失值、汇总行、口径提醒]

## 分析明细
[表格 / 分层拆解]

## 建议动作
| 优先级 | 对象 | 动作 | 依据 | 预期影响 |
|---|---|---|---|---|

## 假设与局限
[哪些数字是估算的、样本不足的部分、需要用户补充的信息]
```

建议必须可执行:写"把 `wireless earbuds waterproof` 在广告组 B 中否定精准",不写"优化否词"。

## 红线

这些事不做,用户要求也要说明原因并拒绝:
- 操纵评论(刷评、返现索评、诱导删差评)
- 刷单、刷流量、操纵 BSR 排名
- 绕过平台限制抓取数据(违反 ToS 的爬虫、模拟登录后台)
- 攻击竞品(恶意跟卖、虚假投诉、恶意差评)

正常的公开数据整理、后台自有报表分析、合规的关键词工具数据处理都没问题。

## 与 detail-master 的分工

本技能负责**数据、诊断、决策**。当结论指向"详情页要改"(CVR 低、图片点击率差、卖点没打中评论里的痛点),把结论和关键词表交给 `detail-master` 落成文案。
